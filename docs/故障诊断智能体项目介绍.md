## 一、我们解决了什么问题？

### 传统方式的痛点

在工程现场，设备发生故障时，工程师需要：

- 📂 **翻阅大量历史报告**：几十份、上百份 PDF 文档，找到相关案例往往需要数小时
- 🧠 **依赖个人经验**：老工程师经验丰富，但知识难以传承；新人上手慢、容易走弯路
- 🔍 **关键词搜索局限**：用关键词搜文件，找不到"隐藏"在文档深处的因果关系

### 举个例子

> 发动机出现"EGR 冷却器漏水"，工程师想知道：**历史上有没有类似案例？根本原因是什么？最终怎么解决的？**
>
> 传统方式：逐份打开 PDF，手动翻找 → **可能需要半天时间**
>
> 用我们的系统：直接输入问题，**3秒内获得答案**，并附带来源文件

## 三、系统是怎么工作的？

### 整体流程（三步走）

```
第一步：知识入库
原始文档（PDF/Word）
       ↓
   AI 阅读理解
       ↓
抽取实体和关系（零部件、故障、原因、措施…）
       ↓
建立"知识图谱"存入数据库

第二步：智能检索
工程师提问
       ↓
系统同时搜索：① 语义相似内容  ② 知识图谱关联
       ↓
召回最相关的历史案例片段

第三步：生成回答
AI 综合多个来源
       ↓
生成有逻辑、有依据的答案
       ↓
呈现给用户（附来源引用）
```

*（配流程图）*

### 与普通搜索的核心区别

| 对比项 | 普通关键词搜索 | 我们的系统 |
|--------|--------------|-----------|
| 搜索方式 | 完全匹配关键词 | 理解语义，找"同一个意思" |
| 关联分析 | 无 | 能找到多步因果关系 |
| 回答形式 | 返回原文片段 | 综合分析，生成完整答案 |
| 知识积累 | 每次从头搜 | 知识沉淀，越用越聪明 |
| 新员工使用 | 需要懂搜索技巧 | 像问人一样自然提问 |

## 四、技术亮点

### 核心技术：LightRAG + 知识图谱

这套系统的核心与普通 AI 问答的区别在于：**多了一层"知识图谱"**

```
普通 RAG 系统：
文档 → 切片 → 向量搜索 → 回答
（只能找"相似"，不理解"关系"）

我们的系统（LightRAG）：
文档 → 切片 → 向量搜索 ↘
              +          → 融合回答
         知识图谱搜索 ↗
（既能找相似，又能沿因果链追溯）
```

### 知识图谱效果展示

系统读完所有故障报告后，自动构建出这样的关联网络：

```
EGR冷却器 ──漏水故障──→ 胶管老化 ──根本原因──→ 材料耐热性不足
                              ↑
                         高温环境 ──影响──→ 加速老化
                              
改进措施 ──对应──→ 更换硅胶胶管
         ──对应──→ 增加隔热
         ──验证──→ 试验通过 ──效果──→ 故障消除
```

### 领域定制化

系统针对**发动机故障 A3 分析报告**做了专门优化：
- 能理解 A3 报告的专有格式（失效网、根本原因、措施、效果）
- 能识别复杂 HTML 表格中的跨行关系
- 输出语言自动调整为中文

## 五、技术栈概览

```
用户界面层：  Web 浏览器（React 前端）
                    ↕
服务层：      LightRAG Server（FastAPI）
                    ↕
AI 模型层：   大语言模型（负责理解和生成）
              向量模型（负责语义搜索）
                    ↕
存储层：      向量数据库（语义检索）
              图数据库 NetworkX（关系推理）
              文档数据库（原文存档）
```

**部署方式**：纯 Python 本地部署，无需购买服务器，笔记本电脑即可运行

## 六、项目价值总结

### 直接价值
- **提效**：故障查询时间从"数小时"压缩到"数秒"
- **传承**：历史经验数字化，不再依赖个人记忆
- **降本**：减少重复踩坑，加速新员工上手

### 延伸价值
- 该技术框架可横向扩展到**其他领域**（质量管理、工艺规程、标准法规查询等）
- 知识图谱可视化，帮助管理层看清**故障规律和高频问题**，辅助决策

### 我在项目中的工作
- 研究并选型 LightRAG 图谱增强 RAG 技术方案
- 针对汽车故障 A3 报告定制知识图谱抽取规则（Prompt Engineering）
- 完成系统本地化部署与调试（解决 OCR、API 对接等工程问题）
- 搭建可交互的 WebUI 演示界面
